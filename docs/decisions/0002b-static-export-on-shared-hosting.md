# ADR-0002b — Статикалық экспорт + PHP endpoint (ортақ хостинг)

**Status:** ✅ ACCEPTED
**Date:** 2026-08-25 · ADR-0002-ні толықтырады (ауыстырмайды)
**Updated:** 2026-08-25 — ашық мәселе шешілді; `.htaccess`-тен екінші ақау табылып түзетілді

## Context

ADR-0002 бойынша стек таңдалғанда деплой ортасы белгісіз еді. Енді белгілі
болды: домен `nureke.kz` **ps.kz-тің ортақ (shared) хостингінде** тұр.

Панельдегі «Инструменты разработчика» бөлімінде:

| Бар | Жоқ |
|---|---|
| PHP 8.3.33, Composer, Git | **Node.js** |
| Журналы, Планировщик задач, Monitoring | |
| Базы данных (MySQL/MariaDB) | **PostgreSQL** |

Диск 2.2 ГБ, трафик айына ~120 МБ. Сайт әзірге `Forbidden` қайтарады —
ештеңе деплой етілмеген.

**Мәселе:** ADR-0002-де таңдалған `output: 'standalone'` + Node runtime +
Prisma + PostgreSQL мұнда **іске қосылмайды**. PHP хостингте Node процесі
жүрмейді. Бұл конфигурация мәселесі емес, ортаның шектеуі.

## Options Considered

| # | Нұсқа | + | − | Шешім |
|---|---|---|---|---|
| A | **Статикалық экспорт + PHP endpoint** | Бар хостингте жұмыс істейді, қосымша төлем жоқ, SEO үшін статика идеал, ops уақыты нөл | Prisma/Postgres CRM жоғалады, ISR жоқ, лид логикасы екі тілде | ✅ **ТАҢДАЛДЫ** |
| B | ps.kz-тен VPS алу | Код мүлдем өзгермейді, docker-compose дайын, CRM жолы ашық | Айына 5–15 мың ₸ + ops уақыты. Business-concept: ops уақыты = сату уақытының шығыны | ❌ әзірге |
| C | Панельде Node.js іздеу | Код өзгермес еді | Панельде Node.js жоқ. Болса да, ортақ хостингтегі Passenger-де Next 16 сенімсіз | ❌ |

## Decision

**A нұсқасы.** Сайт `output: 'export'` арқылы таза HTML/CSS/JS болып жиналады,
лид формасы PHP endpoint-ке кетеді.

### Не өзгерді

| Файл | Өзгеріс |
|---|---|
| `next.config.ts` | `output: 'export'`. `headers()` алынды — статикалық режимде жұмыс істемейді |
| `public/.htaccess` | **жаңа.** Қауіпсіздік хедерлері, таза URL, HTTPS, кэш, құпияларды жабу |
| `src/app/api/leads/route.ts` | **жойылды.** Статикалық экспортта route handler болмайды |
| `public/api/leads.php` | **жаңа.** Сол логика PHP-да: rate limit → бот қақпаны → валидация → скоринг → Telegram → дискіге жазу |
| `public/api/config.example.php` | **жаңа.** Құпиялар үлгісі. Нақты `config.php` — `.gitignore`-де |
| `src/components/lead-form.tsx` | endpoint `/api/leads` → `/api/leads.php` |
| `src/app/sitemap.ts`, `robots.ts` | `export const dynamic = 'force-static'` — экспорт талап етеді |
| `src/app/cases/[slug]`, `services/[slug]` | `dynamicParams = false`; кейс slug-тары `CASES`-тен алынады (себебі төменде) |
| `scripts/prune-empty-cases.mjs` | **жаңа.** Билдтен кейін кейс жоқ болса `/cases` беттерін өшіреді — әйтпесе олар 404 емес, 200 қайтарады (төменде) |
| `package.json` | `postbuild` — сол скрипт `npm run build` соңында автоматты жүреді |

### Қауіпсіздік хедерлерінің жалғыз көзі — `.htaccess`

`next.config.ts` ішіндегі `headers()` статикалық режимде **үнсіз жұмыс
істемейді**. Сондықтан ол алынды. Хедерді өзгерту керек болса — тек
`public/.htaccess` ішінде өзгерт, екі жерде ұстама.

### Лид логикасының жалғыз көзі — `leads.php`

`src/lib/lead.ts`, `telegram.ts`, `rate-limit.ts`, `prisma.ts` енді
**ешқайдан шақырылмайды**. Олар өшірілмеді: B нұсқасына (VPS) қайту керек
болса, дайын тұрсын.

> ⚠️ **Ереже:** валидация не скоринг өзгерсе — `public/api/leads.php`
> өзгертіледі. TS файлдары — мұрағат, олар PHP-мен қатар жүрмейді.
> Екеуін қатар өзгерту міндеті жоқ, бірақ VPS-ке қайтқанда TS жағы
> ескірген болатынын есте ұста.

### Дерекқор орнына — файл

Лид `~/nureke-data/leads.jsonl` файлына жазылады (web root-тан **тыс**,
`.htaccess` қосымша қорғайды). Telegram — негізгі арна, файл — сақтандырғыш.
Екеуі де істемесе, клиентке адал 503 қайтады: үнсіз жоғалтпаймыз.

MySQL қосылмады: `leads.jsonl` қазіргі көлемге жеткілікті әрі нөл конфигурация.
Лид ағыны күніне ондап келе бастағанда қайта қаралады.

## Consequences

- **ISR жоқ.** Мазмұн `src/content/*` ішінде тұр, ол билд кезінде статикаға
  айналады. Мәтін не баға өзгерсе — қайта билд + қайта жүктеу. Бұл шығын емес:
  мазмұн бәрібір кодта өзгереді.
- **Prisma/Postgres CRM жолы жабылды.** Roadmap-тағы №6 таск (Lead CRM,
  34 ұпай) енді B нұсқасын талап етеді. Ол уақыт келгенде — VPS.
- **SEO ұтты.** Статикалық HTML — іздеу жүйелері үшін ең жақсы вариант.
- `npm run start` мағынасын жоғалтты. Жергілікті тексеру: `npm run preview`
  (PHP-дің өз сервері, endpoint-ті де тексереді).

## Шешілген мәселе — `/cases` енді 404 қайтарады

> Бұрын: «ашық мәселе (келесі сессияға)». Шешілді, төменде қалай.

Кейс жоқта `/cases` пен `/cases/<slug>` 404 емес, **200** қайтаратын.
Мазмұны 404 беті еді — кейс мазмұны да, «ПРИМЕР» белгісі де жоқ, яғни
ADR-0003 қорғанысы бұзылмаған. Мәселе тек HTTP кодында болатын: іздеу
жүйесі бос бетті «бар» деп көреді.

### Неге кодта түзетілмеді

Ең дұрысы — бет мүлдем жасалмауы. Ол мүмкін емес екені **тексерілді**:
`generateStaticParams()` бос тізім қайтарса, билд құлайды:

```
Error: Page "/cases/[slug]" is missing "generateStaticParams()"
       so it cannot be used with "output: export" config.
```

Демек беттер жасалады да, содан кейін өшіріледі.

### Шешім: `scripts/prune-empty-cases.mjs` (postbuild)

`npm run build` соңында автоматты жүреді (`postbuild` — ұмытуға болмайтындай).
Кейс жоқ болса `out/cases.html`, `out/cases.txt` және `out/cases/` папкасын
өшіреді. Файл жоқ болғандықтан Apache `ErrorDocument`-пен шын 404 қайтарады —
өлі бет серверге мүлдем жүктелмейді (ADR-0003 үшін бұл қосымша ұтыс).

Үш нәрсе әдейі осылай жасалған:

1. **Мәтін ізделмейді.** Бұрын сыналған «404 маркері бар HTML-дерді өшіру»
   жолы жарамсыз болған: маркер әр беттің RSC-жүктемесінде отыр, сүзгі
   14 беттің бәрін өшіріп жіберген. Мұнда шешімді `hasCases` береді.
2. **Логика қайталанбайды.** `hasCases` қосымша қолданатын
   `src/content/cases.ts`-тен **тікелей** оқылады (Node 22 TS-ті өзі оқиды —
   жаңа тәуелділік жоқ, ADR-0002-нің ережесі сақталды). Нақты кейс
   қосылған сәтте скрипт өзі тоқтайды, ешкім ештеңе қолмен өшірмейді.
3. **Папка да өшіріледі.** Тек `cases.html` өшірілсе, `out/cases/` қалады да,
   Apache 404 емес, 403 қайтарады.
4. **`.env` файлдары оқылады.** Next `.env`-ті өзі оқиды, жалаң Node оқымайды.
   Онсыз мынадай тұзақ болатын (тексерілген, шын болды): `.env` ішіне
   `NEXT_PUBLIC_SHOW_DRAFT_CASES="true"` қоясың → Next кейс беттерін ШЫН
   мазмұнмен жасайды → скрипт айнымалыны көрмей, соларды үнсіз өшіреді.
   Енді скрипт `.env.production.local → .env.local → .env.production → .env`
   тізбегін Next-тің тәртібімен оқиды, нақты орта әрқашан жеңеді.
   Бесеуі де тексерілді.

### Қоса табылған ақау — әр бет 403 қайтаратын

`/cases`-ті нақты Apache-пен тексергенде әлдеқайда ауыр ақау шықты:
**басты беттен басқа әр бет 403 Forbidden қайтаратын.**

Себебі: Next әр маршрутқа екі нәрсе жасайды — `approach.html` файлы **және**
аттас `approach/` папкасы (ішінде RSC-жүктемелері). `.htaccess`-тегі таза URL
ережесінде `RewriteCond %{REQUEST_FILENAME} !-d` шарты тұрған. Ол әр бетте
сол папкаға сәйкес келіп, ережені өшіретін. Одан кейін mod_dir «папка бар»
деп `/approach/` дегенге 301 беретін, ал ол папкада `index.html` жоқ →
`Options -Indexes` → 403.

Түзету екі бөліктен тұрады:

| Өзгеріс | Не үшін |
|---|---|
| `DirectorySlash Off` | mod_dir mod_rewrite-қа дейін 301 беріп үлгеретін. Папка мазмұны ашылмайды — `Options -Indexes` ұстап тұр |
| Екі ережеден де `!-d` алынды | «Папка ма?» орнына «`.html` сіңлісі бар ма?» деп сұраймыз |
| Слэш алу ережесіне `.html` шарты қосылды | Онсыз `/_next/` сияқты шын папкалар mod_dir-мен шексіз циклге түсетін |

### Тексерілді (нақты Apache 2.4 + осы `.htaccess`)

| Тексеру | Нәтиже |
|---|---|
| `/`, `/services`, `/approach`, `/pricing`, `/contact`, 3 қызмет беті | 200 |
| `/cases`, 3 slug беті, жоқ бет | 404 |
| `/services/`, `/approach/` (слэшпен) | 301 → 200, бір секіру, цикл жоқ |
| `NEXT_PUBLIC_SHOW_DRAFT_CASES=true` билді | `/cases` → 200, «ПРИМЕР» белгісі орнында |
| Қауіпсіздік хедерлері | төртеуі де келеді |
| `config.php`, `config.example.php`, `.jsonl` | 403 |
| Кэш | HTML `must-revalidate`, хэшті ассеттер `immutable` |
| `typecheck`, `lint`, `php -l` | таза |

### Қалған ұсақ түйін

`/_not-found` де 200 қайтарады (Next-тің ішкі маршруты). Ол мәзірде де,
sitemap-та да жоқ, сырттан ешкім кірмейді. Керек болса сол скриптке
қосуға болады.

## Қашан B нұсқасына (VPS) көшеміз

Мыналардың бірі болғанда:
1. Lead CRM шынымен керек болғанда (roadmap №6)
2. Лид саны күніне 10+ болып, файлмен жұмыс істеу ыңғайсызданғанда
3. AI-консультант немесе калькулятор сервер жағын талап еткенде

Ол кезде код дайын: `docker-compose.yml`, `Dockerfile`, Prisma схемасы —
бәрі орнында. `next.config.ts` ішіндегі `output` мәнін қайтару жеткілікті.
