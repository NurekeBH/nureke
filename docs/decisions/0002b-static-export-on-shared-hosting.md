# ADR-0002b — Статикалық экспорт + PHP endpoint (ортақ хостинг)

**Status:** ✅ ACCEPTED
**Date:** 2026-08-25 · ADR-0002-ні толықтырады (ауыстырмайды)

## Context

ADR-0002 бойынша стек таңдалғанда деплой ортасы белгісіз еді. Енді белгілі
болды: домен `nureke.kz` **ps.kz-тің ортақ (shared) хостингінде** тұр.

Панельдегі «Инструменты разработчика» бөлімінде:

| Бар | Жоқ |
|---|---|
| PHP 8.3.33, Composer, Git | **Node.js** |
| Журналы, Планировщик задач, Monitoring | |
| Базы данных (MySQL/MariaDB) | **PostgreSQL** |

Диск 2.2 ГБ, трафик айына ~120 МБ. Сайт әзірге `Forbidden` қайтарады —
ештеңе деплой етілмеген.

**Мәселе:** ADR-0002-де таңдалған `output: 'standalone'` + Node runtime +
Prisma + PostgreSQL мұнда **іске қосылмайды**. PHP хостингте Node процесі
жүрмейді. Бұл конфигурация мәселесі емес, ортаның шектеуі.

## Options Considered

| # | Нұсқа | + | − | Шешім |
|---|---|---|---|---|
| A | **Статикалық экспорт + PHP endpoint** | Бар хостингте жұмыс істейді, қосымша төлем жоқ, SEO үшін статика идеал, ops уақыты нөл | Prisma/Postgres CRM жоғалады, ISR жоқ, лид логикасы екі тілде | ✅ **ТАҢДАЛДЫ** |
| B | ps.kz-тен VPS алу | Код мүлдем өзгермейді, docker-compose дайын, CRM жолы ашық | Айына 5–15 мың ₸ + ops уақыты. Business-concept: ops уақыты = сату уақытының шығыны | ❌ әзірге |
| C | Панельде Node.js іздеу | Код өзгермес еді | Панельде Node.js жоқ. Болса да, ортақ хостингтегі Passenger-де Next 16 сенімсіз | ❌ |

## Decision

**A нұсқасы.** Сайт `output: 'export'` арқылы таза HTML/CSS/JS болып жиналады,
лид формасы PHP endpoint-ке кетеді.

### Не өзгерді

| Файл | Өзгеріс |
|---|---|
| `next.config.ts` | `output: 'export'`. `headers()` алынды — статикалық режимде жұмыс істемейді |
| `public/.htaccess` | **жаңа.** Қауіпсіздік хедерлері, таза URL, HTTPS, кэш, құпияларды жабу |
| `src/app/api/leads/route.ts` | **жойылды.** Статикалық экспортта route handler болмайды |
| `public/api/leads.php` | **жаңа.** Сол логика PHP-да: rate limit → бот қақпаны → валидация → скоринг → Telegram → дискіге жазу |
| `public/api/config.example.php` | **жаңа.** Құпиялар үлгісі. Нақты `config.php` — `.gitignore`-де |
| `src/components/lead-form.tsx` | endpoint `/api/leads` → `/api/leads.php` |
| `src/app/sitemap.ts`, `robots.ts` | `export const dynamic = 'force-static'` — экспорт талап етеді |
| `src/app/cases/[slug]`, `services/[slug]` | `dynamicParams = false`; кейс slug-тары `CASES`-тен алынады (себебі төменде) |

### Қауіпсіздік хедерлерінің жалғыз көзі — `.htaccess`

`next.config.ts` ішіндегі `headers()` статикалық режимде **үнсіз жұмыс
істемейді**. Сондықтан ол алынды. Хедерді өзгерту керек болса — тек
`public/.htaccess` ішінде өзгерт, екі жерде ұстама.

### Лид логикасының жалғыз көзі — `leads.php`

`src/lib/lead.ts`, `telegram.ts`, `rate-limit.ts`, `prisma.ts` енді
**ешқайдан шақырылмайды**. Олар өшірілмеді: B нұсқасына (VPS) қайту керек
болса, дайын тұрсын.

> ⚠️ **Ереже:** валидация не скоринг өзгерсе — `public/api/leads.php`
> өзгертіледі. TS файлдары — мұрағат, олар PHP-мен қатар жүрмейді.
> Екеуін қатар өзгерту міндеті жоқ, бірақ VPS-ке қайтқанда TS жағы
> ескірген болатынын есте ұста.

### Дерекқор орнына — файл

Лид `~/nureke-data/leads.jsonl` файлына жазылады (web root-тан **тыс**,
`.htaccess` қосымша қорғайды). Telegram — негізгі арна, файл — сақтандырғыш.
Екеуі де істемесе, клиентке адал 503 қайтады: үнсіз жоғалтпаймыз.

MySQL қосылмады: `leads.jsonl` қазіргі көлемге жеткілікті әрі нөл конфигурация.
Лид ағыны күніне ондап келе бастағанда қайта қаралады.

## Consequences

- **ISR жоқ.** Мазмұн `src/content/*` ішінде тұр, ол билд кезінде статикаға
  айналады. Мәтін не баға өзгерсе — қайта билд + қайта жүктеу. Бұл шығын емес:
  мазмұн бәрібір кодта өзгереді.
- **Prisma/Postgres CRM жолы жабылды.** Roadmap-тағы №6 таск (Lead CRM,
  34 ұпай) енді B нұсқасын талап етеді. Ол уақыт келгенде — VPS.
- **SEO ұтты.** Статикалық HTML — іздеу жүйелері үшін ең жақсы вариант.
- `npm run start` мағынасын жоғалтты. Жергілікті тексеру: `npm run preview`
  (PHP-дің өз сервері, endpoint-ті де тексереді).

## Ашық мәселе (келесі сессияға)

**`/cases` және `/cases/<slug>` беттері 404 емес, 200 қайтарады.**

Себебі: жарияланған кейс жоқ кезде бұл беттер `notFound()` шақырады, бірақ
`output: export` оларды бәрібір файлға жазып қояды. Ішінде кейс мазмұны да,
«ПРИМЕР» белгісі де **жоқ** — тек 404 беті. Яғни ADR-0003 қорғанысы
бұзылмаған, мазмұн ағып кетпейді. Мәселе тек HTTP кодында: іздеу жүйесі
бос бетті 200 деп көреді.

Сыналған әрі **жарамсыз** шешім: билдтен кейін «404 мазмұны бар» HTML-дерді
өшіру. Маркер (`Такой страницы нет`) Next-тің әр бетінің RSC-жүктемесінде
отырады, сондықтан сүзгі барлық 14 бетті өшіріп жіберді. Мәтін іздеу арқылы
ажырату мүмкін емес.

Ұсынылатын жол: билд кезінде `hasCases` мәнін тексеріп, кейс жоқ болса
`.htaccess` ішіне `RewriteRule ^cases(/|$) - [R=404,L]` жолын қосу.
Нақты кейс шыққанда ереже автоматты түрде қосылмайды.

Бұл шұғыл емес: `/cases` сілтемесі мәзірде де, sitemap-та да жоқ, оған
сырттан ешкім кірмейді.

## Қашан B нұсқасына (VPS) көшеміз

Мыналардың бірі болғанда:
1. Lead CRM шынымен керек болғанда (roadmap №6)
2. Лид саны күніне 10+ болып, файлмен жұмыс істеу ыңғайсызданғанда
3. AI-консультант немесе калькулятор сервер жағын талап еткенде

Ол кезде код дайын: `docker-compose.yml`, `Dockerfile`, Prisma схемасы —
бәрі орнында. `next.config.ts` ішіндегі `output` мәнін қайтару жеткілікті.
