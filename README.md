# Nureke

Сайт продуктовой студии и внутренняя CRM.
Домен: **nureke.kz**

> Стратегия, исследование рынка, офферы и решения — в [`/docs`](docs/README.md).
> Начинать чтение оттуда, а не с кода.

## Стек

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind 3 — **статический
экспорт** (`output: 'export'`), плюс PHP-эндпоинт для заявок.

Хостинг `nureke.kz` — общий (shared) у ps.kz: там есть PHP 8.3 и MySQL, но
**нет Node.js и нет PostgreSQL**. Поэтому сайт собирается в чистый HTML, а
форму принимает `public/api/leads.php`.

Обоснование: [ADR-0002](docs/decisions/0002-platform-architecture.md) — выбор
стека, [ADR-0002b](docs/decisions/0002b-static-export-on-shared-hosting.md) —
переход на статический экспорт и его последствия.

Prisma и PostgreSQL остаются в репозитории, но **сейчас не используются**:
они нужны, если проект вернётся на VPS ради CRM (условия — в ADR-0002b).
Правило: новые зависимости добавляются только с письменным обоснованием.

## Локальный запуск

```bash
cp .env.example .env
npm install
npm run dev                  # http://localhost:3000
```

`npm run dev` — обычная разработка. Но dev-сервер **не проверяет то, что
реально уедет на хостинг**: ни статический экспорт, ни PHP-эндпоинт, ни
`.htaccess`. Перед деплоем смотреть настоящую сборку:

```bash
npm run build && npm run preview   # php -S на папке out/, http://localhost:3000
```

⚠️ `npm run preview` поднимает встроенный сервер PHP, а он **не читает
`.htaccess`**. Чистые URL, редиректы и заголовки безопасности там не
работают — их проверяет только настоящий Apache. Что именно зависит от
`.htaccess`, перечислено в ADR-0002b.

## Проверки перед пушем

```bash
npm run typecheck && npm run lint && npm run build
```

## Деплой на ps.kz

Сервера с Node нет — на хостинг уезжает **готовая папка `out/`**, собранная
локально.

```bash
npm run build                # получаем out/ — это и есть весь сайт
```

Дальше — один раз при первом деплое:

1. Содержимое `out/` (включая `.htaccess`, файл скрытый — не потерять)
   загрузить в `public_html/`.
2. `public_html/api/config.example.php` скопировать в
   `public_html/api/config.php` и вписать токен бота и chat_id.
   Этот файл не в репозитории и закрыт `.htaccess` снаружи.
3. Убедиться, что папка заявок лежит **вне** `public_html` — по умолчанию
   `~/nureke-data` рядом с ним. Иначе `leads.jsonl` можно будет скачать
   из интернета.
4. В панели включить SSL. До этого редирект на HTTPS в `.htaccess` смысла
   не имеет.

Дальнейшие деплои — только шаг 1: пересобрать и залить `out/`.

Проверить после заливки:

| Что | Ожидаем |
|---|---|
| `/`, `/services`, `/pricing` | 200 |
| `/cases` | 404 (пока нет опубликованных кейсов) |
| `/api/config.php` | 403 |
| Отправить тестовую заявку | пришла в Telegram |
| Кинуть ссылку себе в WhatsApp | видно превью с картинкой |

## Переменные окружения

Переменные читаются **во время сборки** и запекаются в HTML. Изменил
контакты — нужно пересобрать и перезалить, иначе на сайте останется старое.

| Переменная | Где | Обязательна | Зачем |
|---|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `.env` | да в проде | canonical, sitemap, Open Graph |
| `NEXT_PUBLIC_PHONE` / `_WHATSAPP` / `_TELEGRAM` / `_EMAIL` | `.env` | да | контакты на сайте |
| `NEXT_PUBLIC_SHOW_DRAFT_CASES` | `.env` | нет | показать заготовки кейсов (ADR-0003) |
| `telegram_bot_token` + `telegram_chat_id` | **`api/config.php` на сервере** | желательно | мгновенное уведомление о заявке |

⚠️ Токен бота живёт **не в `.env`**, а в `public_html/api/config.php` на
сервере. `.env` читает Next во время сборки, а заявку принимает PHP уже на
хостинге — он про `.env` ничего не знает. Положишь токен в `.env` —
уведомления просто не придут, молча.

Если Telegram не настроен, заявка всё равно пишется в `leads.jsonl`. Если не
сработало ни то ни другое — форма честно вернёт ошибку и попросит написать в
WhatsApp, вместо того чтобы молча потерять заявку.

## Что уже готово (фаза P1)

- Главная, каталог услуг и три страницы услуг, «Как мы работаем», цены, контакты
- Форма заявки: валидация, honeypot, ограничение частоты, скоринг 0–100
- Приём заявки на PHP: запись в `leads.jsonl` + уведомление в Telegram
- favicon и OG-картинка (превью при отправке ссылки в WhatsApp / Telegram)
- SEO: метаданные, sitemap, robots, разметка Organization / Service / FAQPage
- Тёмная тема, mobile-first, липкая кнопка WhatsApp

## Правила проекта

- Весь текст и цены живут в `src/content/`. В компонентах хардкода нет.
- **Придумывать кейсы запрещено** — [ADR-0003](docs/decisions/0003-experience-led-positioning.md).
  Раздел `/cases` в коде есть, но пока в нём только заготовки (`draft: true`):
  в проде они не видны, в sitemap не попадают, а `/cases` отдаёт 404. Имя
  клиента — только с письменного разрешения, цифры — только подтверждённые.
- Никаких непроверяемых цифр в маркетинговых текстах.
